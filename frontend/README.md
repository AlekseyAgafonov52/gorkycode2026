# Frontend HR

Существующий прототип подключён к FastAPI. Работает без сборки JavaScript и библиотек.
Вакансии, отклики, отчёты и статусы читаются из PostgreSQL через REST API.

## Запуск вместе с backend

Из корня репозитория:

```powershell
docker compose up -d --build
```

Открыть http://localhost:5173/. Swagger backend: http://localhost:8000/docs.
Порт frontend можно изменить через `FRONTEND_PORT` в `.env` (по умолчанию 5173).
После редактирования файлов frontend пересоберите его:

```powershell
docker compose up -d --build frontend
```

Если в новой базе ещё нет данных, загрузите их согласно [HR_API.md](../HR_API.md).
Подготовка отчётов выполняется отдельно на backend; просмотр интерфейса YandexGPT не вызывает.

## Подключение

`config.js` содержит публичный адрес API (`apiBaseUrl`) и тайм-аут запроса.
В Docker используется `/api/v1`: nginx отдаёт статику и проксирует эти запросы в контейнер `api:8000`.
Это работает через один адрес браузера и не зависит от хостового порта backend.
Ключей YandexGPT и параметров PostgreSQL во frontend нет.

`api.js` вызывает эндпоинты:

- `GET /api/v1/vacancies` — вкладки и число откликов;
- `GET /api/v1/vacancies/{id}` — исходный текст вакансии для предпросмотра;
- `GET /api/v1/vacancies/{id}/responses` — карточки со стажем, с поддержкой страниц API;
- `GET /api/v1/responses/{id}/report` — данные отклика, исходный текст, отзыв и сведения о PDF;
- `GET /api/v1/responses/{id}/report/pdf` и `/report/pdf/preview` — исходный PDF и его страницы для вкладки «Отчёт»;
- `GET /api/v1/responses/{id}/report/html` — HTML-версия отчёта, доступная при ошибке встроенного просмотра;
- `PATCH /api/v1/responses/{id}/viewed` — отметка при открытии карточки;
- `PATCH /api/v1/responses/{id}/status` — статус звонка или передача резюме с отзывом.
- `PATCH /api/v1/responses/{id}/source-text` — исходный текст и обновление отчёта.

Карточки разделены по соответствию вакансии. Стаж и внутренний статус показаны в одной строке. У новых откликов синяя обводка и подпись «Новое». После открытия отчёта их карточки становятся серыми. Ширина карточек зависит от содержимого, а их число в строке — от доступного места.
При открытии отклика отметка о просмотре сохраняется на сервере. Если запрос завершился ошибкой, повторное открытие запускает сохранение снова.
Неизвестное ФИО отображается как «ФИО не указано».
Отсутствие ФИО или контактов не снижает оценку: карточки зелёные при совпадении навыков от 70%, иначе жёлтые.

Статусы из меню и подсказок сохраняются в PostgreSQL и видны после перезагрузки. При статусе «Созвониться» подсказка «Созвонились» доступна даже при пустом отзыве. После неё появляется подсказка «Отправить резюме». Статус «Отправлено» означает, что API поставил передачу в очередь Telegram.

На вкладке «Резюме» справа от заголовка «Исходный текст резюме» есть карандаш. Он открывает текстовое поле с кнопками
«Сохранить» и «Отмена». Ctrl/Cmd+Enter сохраняет, Escape отменяет. Отмена ничего не отправляет на сервер.
После сохранения показывается обновлённый отчёт. При ошибке введённый текст остаётся в редакторе;
при одновременной правке другим пользователем сервер возвращает конфликт, сохраняя чужие изменения.
Черновик сохраняется в памяти при переходах между откликами; при закрытии страницы браузер предупреждает
о несохранённом тексте. Открытие и закрытие редактора без правок не меняет переносы строк исходного текста.

Пути в адресной строке используют UUID вакансии и отклика: `#/v/{vacancy_id}/r/{response_id}`.
Страницу отчёта можно открыть напрямую или обновить. Устаревшие запросы при переключении вкладок отменяются.

## Отдельный запуск без nginx

Для локальной разработки измените `apiBaseUrl` в `config.js` на `http://localhost:8000/api/v1`,
запустите backend и статический сервер:

```powershell
python -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

Открывайте именно http://localhost:5173/ — этот origin разрешён CORS backend.
Порт должен быть свободен (Docker-сервис frontend при таком запуске нужно остановить).
Перед сборкой Docker верните `apiBaseUrl: "/api/v1"`.
