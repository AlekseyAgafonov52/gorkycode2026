# Связь HR и департамента через Telegram

HR заполняет в отклике три поля рекомендаций: **сильные стороны**, **слабые места**, **что проверить на собеседовании**. При нажатии «Созвонились, передаю» статус и рекомендации сохраняются одной транзакцией, а бот доставляет руководителю краткую карточку кандидата. Рекомендации рекрутера хранятся отдельно от машинного отчёта. Сохранённые изменения рекомендаций к уже переданному кандидату также доставляются в Telegram.

Один руководитель видит все текущие вакансии и только переданные HR отклики (`forwarded`), включая ранее закрытые. Черновики недоступны. Данные доступны только разрешённым Telegram ID в личном чате.

**После подписания трудового договора руководитель нажимает «Найм закрыт» в карточке конкретного кандидата** и подтверждает действие. На сайте появляются имя нанятого кандидата и сигнал о подписании договора. Вакансия остаётся открытой: HR проверяет результат и самостоятельно нажимает «Закрыть вакансию» на платформе. Если наняты несколько кандидатов, отображаются все. Время найма и Telegram ID ответственного сохраняются в БД.

Отдельная кнопка «Завершить работу с откликом» означает нейтральное завершение независимо от результата и не означает найм. Ошибочную отметку найма можно снять с подтверждением; завершение работы при этом сохраняется, для возврата в работу есть отдельная кнопка. Эти действия не меняют результат звонка, просмотр, архивирование или оценку навыков. Подтверждение действует 10 минут и перестаёт работать после изменения записи. Полная история изменений пока не ведётся.

## Настройка

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. В существующем `.env` в корне проекта заполните:

   ```dotenv
   TELEGRAM_BOT_TOKEN=<токен BotFather>
   TELEGRAM_MANAGER_IDS=<числовой Telegram ID руководителя>
   ```

   `.env` исключён из Git. Не отправляйте токен в чат и не добавляйте его в код.

3. Если ID неизвестен, сначала заполните только токен и запустите сервис. Напишите боту `/id` в личном чате. Эта команда сообщает только собственный ID, не открывая вакансии. Запишите ID в `TELEGRAM_MANAGER_IDS` и перезапустите сервис. При пустом списке доступ к HR-данным закрыт для всех.
4. Соберите и запустите:

   ```powershell
   docker compose --profile telegram up -d --build telegram-bot
   docker compose logs --tail 50 telegram-bot
   ```

   Профиль `telegram` необязательный: обычный запуск Compose не включает бота. Миграции применяются сервисом `migrate`. Бот использует ту же PostgreSQL, что API; YandexGPT для этой функции не вызывается.

5. Для тестирования можно указать свой числовой Telegram ID (не `@username`). Нажмите Start в личном чате бота, чтобы он мог присылать сообщения. На сайте откройте отклик, заполните рекомендации и нажмите «Созвонились, передаю». В боте: `/start` или `/vacancies` → вакансия → «Переданные отклики» → кандидат → «Найм закрыт» → подтверждение. Вакансию после этого закрывает HR на сайте.

После изменения `.env`:

```powershell
docker compose --profile telegram restart telegram-bot
```

На сайте изменения видны после нажатия «Обновить» или перехода на страницу. Автоматического обновления через WebSocket пока нет.

## API

- `PATCH /api/v1/responses/{id}/status`: `workflow_status` и дополнительное поле `recruiter_recommendation` с непустыми строками `strengths`, `weaknesses`, `interview_focus` до 800 символов каждая.
- `PATCH /api/v1/responses/{id}/department-summary`: сохранение `recruiter_recommendation` без изменения результата звонка.
- `PATCH /api/v1/vacancies/{id}/status`: HR закрывает (`closed`) или повторно открывает (`active`) вакансию.
- GET отчёта: `recruiter_recommendation`, `hired_at`, `is_closed`, `closed_at`.
- GET списка и карточки вакансий: `hired_candidates` с ID, именем и временем подтверждения найма. `hired_at != null` означает подписание договора; `is_closed` отдельно означает завершение работы с откликом.

Для совместимости REST принимает смену статуса без рекомендаций; новая форма сайта требует заполнить все три поля перед передачей. Для старых откликов отсутствие рекомендаций явно указано в боте. Подтверждение найма доступно только через авторизованного Telegram-руководителя. REST использует существующий механизм доступа проекта.

## Локальный запуск и проверки

```powershell
.\.venv\Scripts\python.exe -m department_bot --check-config
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m department_bot
.\.venv\Scripts\python.exe -m unittest test_department_bot
```

Проверка конфигурации не обращается к Telegram или БД. Интеграционные тесты требуют `TEST_DATABASE_URL`, используют отдельную временную схему и не отправляют сообщения.

## Работа процесса

Используется [long polling Bot API](https://core.telegram.org/bots/api#getupdates), без публичного порта или HTTPS-адреса сервера. Нужен исходящий доступ к `api.telegram.org`. Если ранее установлен webhook, процесс завершится с пояснением; автоматически удалять чужую конфигурацию он не будет.

Запускайте один экземпляр: PostgreSQL advisory lock не допускает второй процесс для того же бота в этой базе. Cursor обновлений сохраняется атомарно в Docker volume `telegram_state`; не удаляйте volume при обычном перезапуске. Подтверждения подписаны и привязаны к пользователю, кандидату и состоянию записи. Повтор доставки обновления не повторяет найм. Полные резюме и контакты в Telegram не отправляются.

Передача HR ставит флаг доставки в строке отклика PostgreSQL. Бот проверяет очередь между запросами обновлений, обычно в течение 25 секунд при доступном Telegram. После отправки флаг снимается; при временной ошибке доставка повторяется. При сбое между отправкой и подтверждением в БД сообщение может прийти повторно. Обновлённые рекомендации не теряются при доставке предыдущей версии. При отзыве передачи отложенная доставка отменяется.

Существующие отклики не отправляются массово при первой миграции. Доставка начинается с новых передач HR и сохранения изменённых рекомендаций.
