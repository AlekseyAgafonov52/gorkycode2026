# Отклики и должностные инструкции

В каждой из пяти папок:

```text
job_instruction.docx   # Копия предоставленной должностной инструкции
job_vacancy.txt        # Основной источник: актуальная вакансия
отклик 1.json          # Структурированные данные кандидата
отклик 2.json
…
questions/
  input_1.json        # Подготовленный вход, без вызова модели
  prompts_1.json      # Промпты выбранной роли для локального просмотра
  отклик 1.json       # Вопросы, если реальная генерация успешно завершена
  отклик 1.md         # Читаемый отчёт с теми же вопросами
```

Копии инструкций соответствуют папкам:

| Папка | Исходная должностная инструкция |
| --- | --- |
| Frontend developer | Разработчик клиентского ПО.docx |
| Junior Python-разработчик | ПРОВЕРЕНО 2024 Младший инженер по аналитике и работе с большими данными ДИ.docx |
| Junior UX_UI Дизайнер | Дизайнер клиентского ПО.docx |
| Python-разработчик | ПРОВЕРЕНО 2024 Инженер по аналитике и работе с большими данными ДИ.docx |
| QA Engineer Manual | ПРОВЕРЕНО 2024 Инженер по тестированию ПО.docx |

Из корня проекта: `.\.venv\Scripts\python.exe check_candidate.py frontend 1`.

Для проверки файлов без API: `.\.venv\Scripts\python.exe check_candidate.py --all --prepare-only`.

По короткому имени автоматически выбирается IT-профиль роли. Все пять промптов вместе в модель не отправляются. Общие правила и тексты ролей лежат в `prompts/questions/`; старый готовый отчёт обновится только после успешного реального запуска.

В запрос передаются текст вакансии, только раздел «Обязанности» из DOCX и JSON кандидата. Разделы ДИ с общими положениями, правами, ответственностью и квалификационными требованиями исключаются до вызова модели. Вакансия имеет приоритет при расхождениях.

Инструкции не участвуют в пакетном парсинге TXT-откликов. Подробная настройка и имена профилей — в [документации генератора](../QUESTION_GENERATOR.md).
